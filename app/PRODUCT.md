# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

개발자·소규모 개발팀 — 동시에 여러 Claude Code CLI 세션(태스크마다 하나의 지휘자 + 순차 서브태스크 체인)을 여러 git 워크트리에 걸쳐 돌리며, 그 전부를 한 화면에서 감시·지시하고 싶어하는 사람들. 원래는 제작자(marty) 개인 도구로 시작했지만, GitHub 공개 저장소(jxxh204/opentask)로 전환돼 다른 개발자·팀에게도 배포할 제품이다.

## Product Purpose

"병렬 AI 개발 관제탑" — 여러 AI 코딩 에이전트가 동시에 여러 워크트리에서 작업할 때 생기는 감시·조율 문제(무엇이 지금 돌고 있는지, 뭐가 끝났는지, 뭐가 막혔는지, PR/브랜치 상태가 어떤지)를 사이드바 트리 + 탭 워크스페이스 하나로 해결한다. 성공은 사용자가 여러 병렬 세션을 개별적으로 터미널 전환해가며 확인하지 않고도 전체 상황을 한눈에 파악·개입할 수 있는 것.

## Positioning

지휘자(conductor)+서브태스크 체인 구조와, 그 사이의 상호보고 프로토콜(완료/막힘/응답없음을 서브태스크가 스스로 conductor pty에 능동 보고 + OS 알림)이 다른 "AI 코딩 에이전트 뷰어" 류 도구와 구별되는 핵심 메커니즘 — 단순히 여러 터미널을 나열해 보여주는 게 아니라, 에이전트 계층 사이에 실제 보고 체계가 있다.

## Operating Context

- macOS 데스크톱 앱(Electron) — 백엔드(Node) + 프론트(React/Vite) + Electron 셸 3파트 구성, 패키징 배포(electron-builder, 코드사이닝, auto-updater)
- 태스크(폴더) 하나당 지휘자 세션 1개, 그 아래 서브태스크(개발→QA→배포 등 단계) 체인 세션들 — 각각 실제 git 워크트리+브랜치에 연결
- 레포 여러 개를 동시에 등록해 관리(멀티레포), 레포별 "팀 규칙"(브랜치 네이밍, 커밋 컨벤션 등 자유 텍스트)을 에이전트 지시문에 자동으로 실어 보냄
- "비서" — 특정 태스크가 아니라 앱 전체(캘린더, 크론잡, 설정, 레포 관리 등)를 대화로 조작하는 별도의 최상위 에이전트. 탭 워크스페이스 안에서도, 좌측 고정 진입점에서도 접근 가능하며 둘 다 같은 대화가 이어진다.
- 캘린더/휴일/차단 기간, 크론잡, PR·브랜치 상태(gh CLI 연동) 추적도 같은 화면 안에서 다룬다

## Capabilities and Constraints

- Claude Code CLI(`claude` 명령)를 pty(node-pty)로 직접 구동 — 실제 코딩은 전부 이 CLI 세션이 함, 앱 자체는 오케스트레이션·시각화 레이어
- 세션 상태는 SQLite에 영속화(서버 재시작해도 복원), 인메모리 상태(지휘자 대화 피드, blocked/stalled 플래그)는 재시작 시 소실 허용
- 한국어가 1차 UI 언어이며 다국어(i18n) 지원이 진행 중(미확정 — 다른 언어 완성도는 아직 불명확)
- 원격/클라우드 백엔드 없음 — 전부 로컬에서 도는 개인/팀 로컬 도구

## Brand Commitments

- 제품명 "OpenTask"(구 OpenRM에서 개명, 로컬 디렉토리/일부 env 변수명은 하위호환으로 옛 이름 유지). GitHub 조직/저장소: jxxh204/opentask
- 앱 아이콘 확정(macOS Dock/Finder 기준 표준 여백 비율로 맞춤)
- 대화형 화면(비서 등 채팅 UI)의 구도 기준은 ChatGPT/Claude.ai 웹 챗 — 중앙 정렬된 대화 컬럼, 아바타+말풍선, 하단 고정 입력창의 표준 패턴을 그대로 따른다. 색·타이포는 OpenTask 자체 다크 테마(--violet 액센트 등 기존 토큰)를 유지 — 이 표준은 구도·밀도·인터랙션 관례에 한한다, 외부 브랜드 색을 들여오는 게 아니다.

## Evidence on Hand

실사용 스크린샷(사이드바 트리, 탭 워크스페이스, 태스크 매니저 보드 등)은 세션 작업 중 캡처된 것이 저장소 루트에 있음(`real-board.png`, `tree-v5.png`) — 마케팅용으로 검증된 자료는 아님, 별도 확인 없이 인용하지 말 것. 실제 고객 후기·사례·벤치마크 등은 없음.

## Product Principles

- 지휘자와 서브태스크가 서로 조용히 멈추는 일이 없어야 한다 — 완료/막힘/응답없음 모두 능동적으로 위로 보고된다
- 사람이 직접 각 세션을 순회하며 확인하지 않아도 되는 게 목표 — 사이드바 한 곳에서 전체 상태(진행중/완료/막힘/응답없음)가 실시간으로 보여야 한다
- 팀마다 다른 개발 관행(브랜치 네이밍, 커밋 포맷 등)을 코드에 하드코딩하지 않고 자유 텍스트 규칙으로 받아 에이전트에게 그대로 위임한다
- 기존 established 디자인 신호 체계를 지킨다 — red/amber는 신뢰도가 다른 두 종류의 "개입 필요" 신호(확정 vs 추정)로 항상 구분되고 섞이지 않는다

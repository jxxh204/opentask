# OpenTask

🇺🇸 [English](./README.en.md) · 🇰🇷 한국어(현재)

> 태스크 아래 서브태스크를 만들면 각각 격리된 git worktree + AI 코딩 에이전트(Claude Code 등)가 붙는 병렬 개발 관제탑.

![license](https://img.shields.io/badge/license-MIT-blue)

이 폴더는 [OpenRM](../README.md) 모노레포의 앱(Vite+Node 풀스택)입니다 — 리포 이름은 OpenRM이지만 앱 자체의
제품명은 **OpenTask**입니다(내부 코드네임 "MRM" → "OpenRM"을 거쳐 리브랜딩 — 무엇을 최상위 단위로 삼는가를
기준으로 태스크 중심 정체성을 이름에 반영). 같은 리포 상위의 [`agents/`](../agents)·[`skills/`](../skills)가
"무엇을 하는가"의 엔진(Claude Code용)이라면, 이 앱은 태스크·서브태스크·에이전트가 지금 어떤 상태인지 보여주고
직접 지휘하는 관제탑입니다.

## 이게 뭐예요?

태스크 아래 서브태스크를 만들면 각각 격리된 git worktree + 실제 tmux/Claude Code 터미널 세션이 열리고,
태스크 매니저가 순차 "웨이브"로 AI 에이전트를 지휘합니다. 캘린더로 일정을 잡고, 크론잡으로 반복 업무를
자동화하고, PR 리뷰 코멘트에 직접 적용(커밋·푸시까지 진행)·항의(GitHub 공개 답글)까지 — 탭 전환 없이 한
화면에서 처리합니다.

더 자세한 사용법과 스크린별 가이드는 웹사이트 Docs를 참고하세요: https://opentask-website.vercel.app/docs.html

## 설치 & 실행 (설정 없이 바로 동작)

```bash
git clone https://github.com/jxxh204/opentask
cd opentask/app
npm install
npm run start   # 백엔드(8770)+프론트(5180) 한 번에, 색으로 구분된 로그. Ctrl+C로 둘 다 종료
```

데스크톱 창(Electron)으로 바로 띄우려면:

```bash
npm run electron:dev
```

설정 없이 실행하면 **데모 데이터**로 전체 화면 구조(태스크 트리·캘린더·크론잡·비서)를 먼저 둘러볼 수
있습니다. 실제 레포에 연결하려면 온보딩 화면에서 "레포 추가"를 누르세요.

## 구조

```
openrm/
├── agents/, skills/      # 엔진 (Claude Code용, 상위 README 참고)
└── app/                  # ← 여기
    ├── server/           # 백엔드 (Node) — 태스크/폴더/서브태스크/캘린더/크론잡 상태를 관리
    ├── electron/         # macOS 데스크톱 앱 셸(main.cjs) — 백엔드를 detached 프로세스로 구동
    ├── src/              # 프론트엔드 (React CSR, Vite + TS)
    ├── vite.config.ts    # 5180 → 백엔드 8770 프록시
    └── config.example.sh # 전체 설정 항목(선택)
```

## 뭐가 들어있나 (실제 탭 구조)

"모든 메뉴는 탭에서 나온다" 원칙에 따라 별도 페이지/라우트 없이, 태스크·서브태스크를 열면 아래 탭들이
워크스페이스 안에서 열립니다.

| 탭 | 하는 일 |
|---|---|
| 메모 | 메인 태스크 없이 독립적으로 존재하는 서브태스크 — 이름·설명만 가진 가벼운 메모, 사이드바에서 드래그로 재정렬 |
| 태스크 매니저 | 서브태스크가 생기면 자동으로 시작되는 AI 지휘자 — 순차 웨이브 실행 + 라이브 터미널 + 계획/지시/보고 로그 |
| 다이어그램 | 서브태스크 체인을 조립 라인처럼 요약한 보드 — 상태(대기/진행/종료)와 예정 기간 |
| 캘린더 | 서브태스크 일정을 주/월 단위로 배치·드래그 재조정, 차단 기간(QA 기간 등) 표시 |
| 크론잡 | N분마다·매일·매주 예약 — 액션은 "새 일감 생성"으로 의도적으로 제한 |
| 모델 배정 | 설계·태스크 매니저·코딩·리뷰·QA 등 작업 종류별 AI 모델 정책 |
| 팀 규칙 | 레포당 자유 텍스트 4칸(일반 규칙/태스크 작성 규칙/브랜치 규칙/개발 시작 전 조건)으로 에이전트 지시문에 실릴 팀 규칙 정의 |
| 비서 | 태스크 하나가 아니라 앱 전체(캘린더·크론잡·설정)를 대화로 조작하는 최상위 에이전트 |
| 터미널 · 로컬 서버 · 브라우저 · 클로드 세션 | 서브태스크 워크트리의 실제 tmux 터미널, dev 서버, 임베디드 브라우저, 즉석 Claude Code 세션 |
| PR 리뷰 | 리뷰 코멘트에 "리뷰 적용"(살아있는 세션에 지시 주입, 커밋·푸시까지 진행) / "리뷰 항의"(GitHub 공개 답글) |

전체 설정 항목은 [`config.example.sh`](./config.example.sh) 참고 — 대부분 선택사항이고, 아무것도 안
채워도 위 기능 대부분이 동작합니다.

## 보안

로컬 실행을 전제로 설계됐지만 git/셸/터미널을 직접 실행할 수 있는 서버라, 기본값은 `127.0.0.1` loopback
바인딩입니다. `OPENRM_HOST=0.0.0.0`으로 LAN에 열면 토큰 인증이 자동으로 요구됩니다(콘솔에 출력). 그래도
신뢰할 수 없는 네트워크에는 노출하지 마세요.

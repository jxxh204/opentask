태스크만 만들면,
워크트리·세션은 알아서 돌아간다

워크트리, 브랜치, 터미널 세션 — 전부 태스크 아래 디테일입니다. 할 일을 태스크로 적으면 격리된 git worktree가 열리고, 태스크 매니저가 순차 웨이브로 AI 에이전트를 지휘합니다. 캘린더로 일정을 잡고, 크론잡으로 반복 업무를 자동화하고, PR 리뷰에 직접 적용·항의까지 — 탭 전환 없이 한 화면에서.

macOS용 다운로드 Docs 보기
macOS 지원 · MIT 라이선스 · 오픈소스 · 로컬 우선(데이터는 내 컴퓨터에 저장)
“리뷰에 ‘적용’을 누르면, 실제로 그 서브태스크의 살아있는 터미널 세션에 지시가 전달됩니다.”

OpenTask는 상태를 보여주기만 하는 대시보드나 태스크 트래커가 아닙니다. 실제 tmux 세션·git worktree·GitHub API에 직접 물려 있는 제어판입니다. PR 리뷰에 적용을 누르면 커밋·푸시까지 실제로 진행되고, 항의를 누르면 실제 GitHub에 공개 답글이 게시됩니다. 캘린더에서 일정을 드래그하면 서브태스크의 실제 예정일이 바뀌고, 크론잡은 정해진 시각에 진짜로 새 일감을 만듭니다 — 일반 대시보드는 이 살아있는 연결을 흉내낼 수 없습니다.

한 화면에서 끝나는 워크플로

태스크 생성부터 에이전트 실행, PR 리뷰, 일정 관리까지 — 탭 전환 없이 판단하고 조작합니다.

태스크 매니저

서브태스크가 생기는 순간 AI 오케스트레이터가 자동으로 통제를 시작해 순차 웨이브로 지휘합니다. 실시간 터미널과 계획·지시·보고 로그를 함께 봅니다.

터미널 · 브라우저 · 로컬 서버

서브태스크(워크트리)마다 실제 tmux 터미널, 임베디드 브라우저, 로컬 dev 서버 탭을 열어 결과를 바로 확인합니다.

캘린더

서브태스크 일정을 주/월 단위로 배치하고 드래그로 재조정합니다. QA 기간처럼 막아야 하는 구간은 차단 기간으로 표시합니다.

PR 리뷰

리뷰 코멘트에 적용을 누르면 실제로 커밋·푸시까지 진행되고, 항의를 누르면 GitHub에 공개 답글이 게시됩니다.

크론잡

N분마다 · 매일 · 매주 — 정해진 시각에 실제로 새 일감을 자동 생성합니다.

비서

캘린더 · 크론잡 · 설정까지 — 태스크 하나가 아니라 앱 전체를 대화로 조작합니다.

제품 원칙

살아있는 연결을 우선한다

상태 스냅샷보다, 실제 세션 · 저장소 · API에 물린 실제 제어를 항상 우선합니다.

컨텍스트 스위칭 제거가 핵심 가치다

GitHub · Slack · Notion · 터미널을 오가지 않고, 한 화면에서 판단하고 조작할 수 있어야 합니다.

팀 규모에 맞게 확장하되 속도를 잃지 않는다

소규모 팀이 함께 쓰지만, 무거운 협업 오버헤드(권한 체계, 승인 플로우)를 강제하지 않습니다.

되돌릴 수 없는 실제 액션은 명확히 구분한다

GitHub 게시, 세션 지시처럼 되돌릴 수 없는 액션은 로그성 정보와 시각적으로 분리됩니다.

설정 전에는 안전하게 게이팅한다

필수 설정이 끝나기 전까지 위험하거나 의미 없는 상태로 핵심 페이지에 진입시키지 않습니다.

절제된 시맨틱 컬러, 라이트/다크 모두 지원

상태색만 뚜렷하게 씁니다 — 파랑은 PR/링크, 초록은 진행·성공, 호박색은 대기·주의, 빨강은 실패·삭제.

PR · 링크 진행 · 성공 · 병렬 대기 · 주의 실패 · 삭제 에이전트 · 선택

MIT 라이선스로 공개된 제어판

소스를 직접 빌드해 셀프호스팅하거나, GitHub에서 기여할 수 있습니다. 로컬 실행이 기본이며, 기본값은 127.0.0.1 loopback 바인딩입니다.

See it in action

Real screen recordings, not mockups — pick a tab.

“Drag a task on the calendar and its real due date changes — a cron job fires and a new task is genuinely created, not just logged.”

OpenTask isn't a dashboard or a task tracker that only shows you state. It's a control panel wired directly into real tmux sessions, git worktrees, and a scheduler. Drag an item on the calendar and the subtask's real due date changes; a cron job fires at its scheduled time and genuinely creates a new task; the moment a subtask exists, a live agent session is already running inside its own worktree — a plain dashboard can't fake this kind of live connection.

A workflow that never leaves one screen

From creating a task to running agents and managing schedules — without switching tabs.

Task Manager

The moment a subtask appears, the AI orchestrator takes over and drives the queue in sequential waves — watch the live terminal alongside its plan / dispatch / report log.

Terminal · Browser · Local Server

Each subtask (worktree) gets real tmux terminals, an embedded browser, and a local dev-server tab so you can check results on the spot.

Calendar

Lay subtasks out on a week or month view and drag to reschedule. Mark off periods — like a QA freeze — where work shouldn't happen, as blocked periods.

Cron Jobs

Every N minutes, daily, or weekly — a new task is genuinely created for you at the scheduled time.

Overmind

Calendar, cron jobs, settings — the Overmind runs the whole app by conversation, not just one task.

Product principles

Live connections come first

Real control wired to actual sessions, repos, and APIs always wins over a state snapshot.

Removing context switching is the core value

You should be able to decide and act from one screen — no bouncing between GitHub, Slack, Notion, and terminals.

Scale with the team, without losing solo-operator speed

Built for small teams working together, without forcing heavy collaboration overhead like permission systems or approval flows.

Irreversible real actions are clearly set apart

Actions with real consequences — a cron job creating a genuine task, an agent's live session receiving your instructions — are visually separated from mere log information.

Safely gated until setup is done

You're never dropped into a risky or meaningless state on a core screen before required setup is complete.

Restrained semantic color, light and dark alike

Only state colors stand out — blue for PRs/links, green for progress/success, amber for waiting/caution, red for failure/deletion.

PR · link progress · success · parallel waiting · caution failure · delete agent · selection

A control panel released under MIT

Build it from source and self-host it, or contribute on GitHub. Local execution is the default, and it binds to 127.0.0.1 loopback out of the box.
